# KnuMail v1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build KnuMail v1, a mailbox addon for WoW Forever: open all with filters, checkbox selection, address book, click shortcuts and clean tooltips, written from scratch.

**Architecture:**
- Plain Lua addon with no libraries. Every file gets the shared namespace with `local _, ns = ...`.
- Pure logic lives in `Names`, `Classify`, `Rules`, `Selection` and `Book`, and is tested outside the game with a fake WoW API.
- Thin UI files hook Blizzard's Forever mail frame (`InboxFrame`, `MailItem1..7`, `SendMailNameEditBox`) and call the logic.

**Tech Stack:** Lua 5.1 subset (WoW), FrameXML API of Forever 1.60.1 (`## Interface: 16001`), tests run with Lua 5.4 (`DEVCOM.Lua`), Python + Pillow for media (already done).

**Spec:** `docs/superpowers/specs/2026-11-13-knumail-design.md` (read it first; also `docs/investigacion.md`).

## Global Constraints

- Repo: `E:\Repositorios\Personal\KnuMail`. Conventions copied from `E:\Repositorios\Personal\KnuUI`: `Locales.lua` with English keys and esES/esMX values, `.pkgmeta`, MIT.
- No code from Postal, Posty or Postmester may be copied. They may only be studied as references; copies of them sit in the scratchpad, never in the repo.
- KnuMail never calls `SendMail` (`HasRestrictions = true`). It only fills fields.
- Open-all never opens COD mail or GM mail automatically. Mail with gold from a stranger (not alt, friend or guild, not auction house) is skipped **entirely** (spec 5.8a).
- Item pace: one item at a time, at least `0.15` s apart (Forever's `OPEN_ALL_MAIL_MIN_DELAY`), and only when `C_Mail.IsCommandPending()` is false.
- Recent recipients: max `20`. Inbox rows per page: `INBOXITEMS_TO_DISPLAY` (7 in Forever).
- Saved variable: `KnuMailDB` (account-wide). Alts keyed by full name.
- All user-facing text goes through `ns.L` (English key, Spanish in `Locales.lua`).
- Commit messages in Spanish, small commits, with the attribution trailer from the session.

## Review Focus

1. **Index shift:** when a mail empties, the game deletes it and every later index moves down by one. The engine must re-read headers each step and never keep a cached index list. Test: `openall_index_shift` in Task 5.
2. **Bags fill up mid-run:** it must stop with a message after the first "inventory full" error and never retry in a loop. Test: `openall_stops_on_full_bags` in Task 5.
3. **Mailbox closed mid-run:** stop without errors and keep no pending timers. Test: `openall_stops_on_mail_closed` in Task 5.
4. **Stranger mail with gold and items:** skip the whole mail, items included. Test: `rules_stranger_gold_with_items_skips_all` in Task 4.
5. **Two identical mails** (same sender, subject, money): the selection must still tell them apart by inbox order. Test: `selection_identity_tiebreak` in Task 6.

### Task 4: Mail reading, classification and open rules

**Files:**
- Create: `Inbox.lua`, `Classify.lua`, `Rules.lua`
- Test: `tests/test_rules.lua`

**Interfaces:**
- Produces:
  - `ns.Inbox.Read(index) -> mail`, where mail = `{index, sender, subject, money, cod, itemCount, isGM, wasReturned, invoiceType, kind}`. It wraps `GetInboxHeaderInfo` and `GetInboxInvoiceInfo`; `kind` comes from `Classify`.
  - `ns.Inbox.Identity(mail, occurrence) -> string`: `sender|subject|money|cod|daysLeft rounded to 0.01|occurrence`. `occurrence` is the 1-based count of earlier mails in the inbox with the same other fields. Used by Tasks 5, 6 and 8.
  - `ns.Classify.Kind(subject, invoiceType, subjects) -> "ahSold"|"ahWon"|"ahExpired"|"ahCancelled"|"ahOutbid"|"other"`. `invoiceType == "seller"` gives `ahSold` and `"buyer"` gives `ahWon`. The others come from matching `subject` against the client's localized globals (Task 1 probe), with each `%s` turned into `.+`.
  - `ns.Rules.Decide(mail, openAll, isKnown, explicit) -> action, reason`:
    - `action`: `"take"`, `"gold"` or `"skip"`.
    - `reason`: `"cod"`, `"gm"`, `"strangerGold"`, `"filter"`, `"empty"` or `nil`.
    - `explicit == true` (checkbox) ignores filters and the stranger rule, but **never** COD.
    - `openAll.goldOnly` turns `"take"` into `"gold"` and skips mails without money (`"empty"`).

### Task 5: Open-all engine, button, menu and summary

**Files:**
- Create: `OpenAll.lua`
- Test: `tests/test_openall.lua`

**Interfaces:**
- Consumes: `ns.Inbox.Read`, `ns.Rules.Decide`, `ns.Names.IsKnown`, `ns.db.settings.openAll`.
- Produces:
  - `ns.OpenAll.Start(opts)`, where `opts = { goldOnly = bool, only = {identity=true...} | nil }`. `only` restricts the run to the selected mails and sets `explicit`.
  - `ns.OpenAll.Stop(reasonText)` and `ns.OpenAll.IsRunning() -> bool`.
  - `ns.OpenAll.Summary() -> { gold = n, opened = n, skipped = { [reason] = n } }`, printed with `ns.Print` when a run ends.
- **Algorithm (not fixed by the tests):** each tick re-reads `GetInboxNumItems()` and walks from index 1 up, keeping a set of identities already decided in this run. It acts on the first mail that is not yet decided, and only one action happens per tick:
  - Money first (`TakeInboxMoney`), then the first attachment slot (`TakeInboxItem(i, slot)`).
  - The next tick waits for `MAIL_SUCCESS`, `MAIL_INBOX_UPDATE` or `0.15` s, and for `C_Mail.IsCommandPending() == false`.
  - Stops when:
    - Free bag slots are `<= keepFree` (sum of `C_Container.GetContainerNumFreeSlots` for bags 0-4).
    - `UI_ERROR_MESSAGE` reports `ERR_INV_FULL`.
    - `MAIL_CLOSED` fires.
    - No undecided mail is left; at that point it calls `CheckInbox()` once if `C_Mail.CanCheckInbox()` allows it and the server holds more mail than `GetInboxNumItems` shows, and stops after that.
- **UI:** a button labeled `L["Open all"]`, anchored according to the Task 1 decision.
  - Alt-click runs gold only.
  - Its arrow opens a menu with the 6 kinds, "Take gold from strangers" (`strangerGold`), "Keep N bag slots free" (0, 2, 4, 6) and "Gold only" (permanent).
- [ ] **Step 1: Tests** against the fake API:
  - `openall_takes_known_mail`.
  - `openall_index_shift`: 3 mails; mail 1 empties and is removed from `FAKE.inbox`; mails 2 and 3 are still taken.
  - `openall_skips_stranger_gold_and_counts_it`: `skipped.strangerGold == 1`.
  - `openall_stops_on_full_bags`: `FAKE.freeSlots = 0`, `keepFree = 0`. The first take fires `ERR_INV_FULL`; the run stops, `IsRunning() == false`, and there are no more `TakeInboxItem` calls.
  - `openall_keeps_free_slots`: `keepFree = 2`, `freeSlots = 2`, gives 0 items taken.
  - `openall_stops_on_mail_closed`.
  - `openall_respects_min_delay`: no two take calls less than `0.15` s apart in `FAKE.time`.
  - `openall_only_selected`.
